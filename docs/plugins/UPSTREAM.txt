Production slicing dispatcher adaptations (2026-10-22):
- PluginSlicing resolves the entire manifest strictly and pins capability consumers for the whole Print::process pass.
- Effective configs use a thread-local per-pass snapshot, never the live GUI preset; blocking UI calls from slicing are rejected.
- Static PrintConfig stores selection, manifest and overrides for invalidation; runtime instance generation/config signatures rebuild on the next process pass after global config edits or same-version reloads.
- Core uses a factory/lease with teardown drain. Registry acquisition increments consumer references atomically with lookup; active unload/disable/removal/replacement is refused; Script dispatch also takes this pin.
- ctx.orca_version reports the actual Snapmaker_VERSION through the existing host header.
- All 13 public stage enum/context bindings now have real native seams. Conditional stages are tested with qualifying fixtures; no-op and warm in-memory paths retain their conditional behavior.
- Release on-disk slice caches cannot preserve plugin identities/configuration or XYZ paths. Plugin/contour tasks refuse these legacy caches and rebuild rather than silently restoring a lossy graph.
- XY-only release wipe is disabled for spatial paths. Local-Z micro-layer height overrides combined with contouring currently raise an explicit unsupported-combination error.
- Configuration/package changes enqueue per-plate invalidation outside Python/config locks. Automatic restart remains conditional on the host build and setting.
- ResourceTexture has a validated package registry, image ownership and the pinned native TextureBake pipeline. The current GUI consumer bakes into mesh; editable texture layers/UV/painting are not yet fully migrated.
- A production executable exports 10 actual SDK modules; generated .pyi and a hashed manifest are checked against its introspection. This does not claim the remaining PreciseSeam or device symbols exist.
